# 边界迁移清单

本文是《架构边界设计》的执行清单，用于冻结现有协议的目标所有者。迁移完成前，类型仍可暂时位于原程序集，但不得继续向错误的所有者增加定义。

## 所有权判定规则

- 内核拥有可复用机制和不变量，不拥有实验学科词汇。
- 模块拥有自己产生、解释和校验的协议标识。
- 课程只引用模块协议并提供实例数据，不声明新的运行时协议。
- 表现层只消费科学事件，不回写权威科学状态。
- Unity 适配层只负责场景输入、空间事实和表现执行。

## 第一阶段冻结规则

从本清单建立起执行以下限制：

1. 不向 `RelationKind`、`CoreCapabilityIds`、`InteractionSemanticActionIds` 或事实字段所有者目录增加跨模块协议。
2. 不在 `Runtime` 中增加化学、氧气课程或 Unity 专用引用。
3. 不让 Chemistry 引用 OxygenCourse，也不让 UnityAdapter 的通用运行时引用 Chemistry。
4. 不新增横向动作专用课程列；新配置需求先归入模块参数模式。
5. 迁移产生破坏性变化时一次性修改调用方，不添加 `.vN` 或旧协议分支。

## 提交切分

- 阶段一：迁移清单和程序集依赖守卫。
- 阶段二：模块清单、注册上下文、冻结及冲突校验。
- 阶段三：交互、测量、化学和教学协议迁移。
- 阶段四：组件与选择器创作模型及课程编译器切换。
- 阶段五：氧气课程迁移与行为验收。
- 阶段六：删除旧定义、旧列和临时适配。

## 当前实施状态

- 阶段一已完成：现有定义所有权和生产程序集依赖方向已经冻结。
- 阶段二已完成：运行时模块清单、依赖解析、事实读取器、状态操作、事件投影、持续过程推进器和注册冻结已具备统一入口。
- 课程编译产物已显式记录所需运行时模块；会话创建前会校验模块是否安装，不再由运行环境隐式决定课程能力。
- 阶段三已开始：`StructuredFactField` 只保留通用标识值对象，事实字段已拆入内核、交互、空间和教学所有者目录；所有调用方已直接迁移，未保留兼容入口。
- 交互动作所有权已迁移：`CoreSemanticActionIds` 已删除，动作由 `InteractionSemanticActionIds` 集中声明；运行时、Unity 输入适配器和课程调用方均已直接切换。
- 阶段三后续：把协议所有者目录迁入对应程序集，并继续迁移能力、关系和化学协议。
