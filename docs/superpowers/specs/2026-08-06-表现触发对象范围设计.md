# 表现触发对象范围设计

## 目标

在不增加课程表数量、不引入 Unity 资源引用的前提下，让课程作者能够明确限定：某条表现只由哪一对实验对象之间的语义操作触发。

例如，“药匙从高锰酸钾广口瓶拿出”应隐藏该试剂瓶中的内容，但其他器材执行“拿出”时不应触发这条表现。

## 边界

- `表现.csv` 仍只描述设备无关的表现语义，不保存预制体、材质、音频或组件引用。
- 内核和 Chemistry 不解释 Unity 手势，也不决定具体动画。
- UnityAdapter 的创作与编译层负责把自然语言课程配置展开为表现触发契约。
- `主体选择方式`、`主体选择值` 继续表示“表现作用到谁”，不能兼作触发对象。

## 配置契约

`表现.csv` 增加两个可选列：

```csv
表现标识,触发类型,触发值,触发来源,触发目标,主体选择方式,主体选择值,表现信号,作用位置,位置标识,参数
```

- `触发来源`：语义操作请求中的来源实体标识；留空表示不限制来源。
- `触发目标`：语义操作请求中的目标实体标识；留空表示不限制目标。
- 两列彼此独立，可以只填写一列。
- 对课程初始化、领域事件和状态持续等没有来源/目标对象的触发类型，两列必须留空；填写时产生面向作者的编译诊断。
- 触发来源或目标引用不存在的课程实体时，编译失败并定位到 `表现.csv` 对应记录。

氧气课程中的固体取用表现配置为：

```csv
舀取后隐藏试剂瓶内容,动作成功,取出,药匙,高锰酸钾广口瓶,实体,高锰酸钾广口瓶,隐藏渲染器,表现插槽,插槽.内容,
舀取后显示药匙内容,动作成功,取出,药匙,高锰酸钾广口瓶,实体,药匙,显示渲染器,表现插槽,插槽.内容,
```

## 数据流

1. 草稿读取器读取两个可选列，并保存在 `CourseDraftPresentation`。
2. 草稿展开器原样写入既有表现覆盖蓝图的“触发来源、触发目标”字段。
3. 规范化验证器验证实体引用与触发类型的适用性。
4. 课程编译器把两个字段写入 `CoursePresentationRuleDefinition`。
5. 运行时表现协调器同时匹配触发类型、触发值、来源和目标，再向 Unity 表现执行器发送命令。

该链路不根据表现名称或器材名称推断角色，避免隐藏规则和课程硬编码。

## 编辑器体验

- 两列使用自然中文，不暴露内部协议键。
- 新建课程默认留空，因此普通的全局提示不增加配置负担。
- 工作台将两列解释为可选对象引用，并从当前课程实体中提供候选项。
- 检查区的错误信息应说明具体表现记录及不存在或不适用的对象字段。

## 测试与验收

- 草稿读取和往返保存保持两个字段。
- 留空时生成不限制来源、目标的表现规则。
- 同时填写时，仅精确对象组合触发表现。
- 不存在的实体和不适用的触发类型产生结构化诊断。
- 氧气课程“舀取高锰酸钾”表现只响应“药匙 → 高锰酸钾广口瓶”的“取出”操作。
- 试管夹仍只由内核授权“调整位置”；抓住、拖动、旋转等手势由 UnityAdapter 判断和执行。
- 重新运行 Engine、UnityAdapter、Chemistry、OxygenCourse 的 EditMode 测试和 Engine PlayMode 测试。

## 不包含的内容

- 不增加第十一张课程表。
- 不自动从表现名称、操作特例或器材模板推断触发对象。
- 不在内核中新增化学器材、Unity 手势或表现资源类型。
- 不恢复任何旧表读取链路或版本兼容逻辑。
